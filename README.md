# ObsidianNotification

Android-приложение для локальных напоминаний из markdown-заметок Obsidian.

Приложение читает задачи и обычные напоминания из одного файла, нескольких файлов или целой папки, планирует системные Android-уведомления, умеет повторять их по интервалу, работать с подзадачами и записывать изменения обратно в markdown.

Основная идея простая: Obsidian остается местом, где вы храните задачи, а ObsidianNotification отвечает за надежные напоминания на телефоне.

## Текущее состояние

Версия в проекте: `1.2.0`

Минимальная версия Android: `8.0 (API 26)`

Целевой Android SDK: `35`

## Что уже есть

### Источники данных

- один markdown-файл
- несколько markdown-файлов
- папка с заметками
- управление источниками из приложения
- создание нового markdown-файла прямо из экрана источников
- доступ через Storage Access Framework
- сценарий работы с Obsidian vault и Syncthing

### Парсинг задач

- чекбокс-задачи `- [ ] ...`
- обычные строки-напоминания без чекбокса
- вложенные markdown checklist-строки как подзадачи
- задачи только с датой
- задачи только со временем
- задачи без повтора
- поддержка пользовательских ключевых слов парсинга через настройки
- понятные ошибки парсинга

### Поддерживаемые поля

- `@due(...)`
- `@repeat(...)`
- `@repeatUntilDone(...)`
- `@tag(...)`
- `@priority(...)`
- `@group(...)`
- `@grace(...)` — сколько времени задача не считается просроченной после `due`
- `@snooze(...)` — индивидуальный интервал отложения для задачи
- `@skipped`
- обычные Obsidian-теги вида `#work`

### Уведомления

- локальные Android-уведомления без облачных сервисов
- канал уведомлений
- exact alarms, если система разрешает
- fallback на неточный alarm, если exact alarms запрещены
- действия из уведомления:
  - выполнить
  - отложить
  - пропустить
- повтор по `@repeat(...)`
- настойчивый повтор до выполнения по `@repeatUntilDone(...)`
- индивидуальный label и логика отложения для задач с `@snooze(...)`

### Состояния задач

- ожидает
- выполнена
- пропущена
- просрочена

`overdue` вычисляется автоматически по `due + grace`, а `completed` и `skipped` являются сохраненными состояниями.

### UI и навигация

- экран задач
- экран календаря
- нижняя навигация `Задачи / Календарь`
- левый drawer с app-level навигацией
- Material 3-стиль
- темная, светлая и системная тема
- onboarding первого запуска

### Работа со списком задач

- группировка и фильтрация
- скрытие приватных задач по пользовательскому private marker
- статусный фильтр
- multi-select режим
- массовые действия:
  - выполнить
  - пропустить
  - отложить
  - удалить
- swipe-действия:
  - вправо — пропустить
  - влево — удалить
- snackbar undo для пропуска и удаления
- вертикальный swipe вниз/вверх для раскрытия и сворачивания подзадач у родительских задач

### Календарь

Календарь использует те же задачи и фильтры, что и основной список.

Поддерживается:

- режим `Неделя`
- режим `Месяц`
- режим `Год`
- выбор дня
- список задач выбранного дня
- маркеры задач по статусам
- быстрый переход к созданию задачи на выбранную дату
- те же swipe-действия для задач, что и в основном списке

### Редактирование

Есть два независимых сценария:

1. `TaskEditActivity` — редактор одной задачи в sheet-стиле
2. `MarkdownFileEditActivity` — редактор всего markdown-файла

UI-редактор задачи умеет:

- создавать и редактировать задачи
- показывать live markdown preview
- редактировать повтор, repeat-until-done, snooze и grace
- работать с подзадачами
- предупреждать о несохраненных изменениях

Markdown-редактор умеет:

- открыть исходный файл целиком
- перейти к строке задачи
- сохранить изменения обратно в файл
- вставлять быстрые шаблоны вроде `@due(...)` и `@repeatUntilDone(...)`

### Подзадачи

- парсятся из вложенных markdown checklist-строк
- отображаются внутри родительской карточки
- имеют прогресс у родительской задачи
- редактируются тем же editor pattern, что и обычные задачи
- поддерживают:
  - выполнение
  - пропуск
  - удаление
  - редактирование

### Надежность

- локальный кэш задач
- защита от битых и частично синхронизированных файлов
- восстановление напоминаний после:
  - перезагрузки устройства
  - обновления приложения
  - смены часового пояса
  - изменения системного времени
- логирование ошибок

## Быстрый старт

1. Установите APK на телефон.
2. Откройте приложение.
3. Выберите источник:
   - файл
   - несколько файлов
   - папку с заметками
4. Разрешите уведомления.
5. Если Android попросит, разрешите exact alarms.
6. Добавьте задачу в заметку.

Пример:

```markdown
- [ ] Купить лекарство @due(2026-04-20 19:00) @repeatUntilDone(15m) @group(health)
```

## Примеры синтаксиса

```markdown
- [ ] Купить лекарство @due(2026-04-20 19:00) @repeat(15m)
- [ ] Проверить ответ @due(19:00) @repeatUntilDone(15m) @grace(10m)
- [ ] Позвонить врачу @due(2026-04-20) @snooze(30m)
Plain reminder @due(2026-04-20 21:00) @group(home)
```

Подзадачи:

```markdown
- [ ] Подготовить отчет @due(2026-04-22 10:00) @group(work)
  - [ ] Собрать данные @due(2026-04-22 08:30)
  - [ ] Проверить цифры @repeatUntilDone(15m) @priority(high)
```

Поддерживаемые варианты `@due(...)`:

- `@due(2026-04-20 19:00)`
- `@due(2026-04-20T19:00)`
- `@due(20.04.2026 19:00)`
- `@due(2026-04-20)`
- `@due(19:00)`

Поддерживаемые интервалы:

- `15m`
- `2h`
- `1d`

## Сценарий с Syncthing

Рекомендуемый сценарий:

1. Синхронизируйте vault или отдельную папку задач через Syncthing на телефон.
2. В приложении выберите синхронизируемую папку или файлы через Android picker.
3. Дайте write-доступ, если хотите выполнять, пропускать и редактировать задачи из приложения.
4. После изменений на ПК дождитесь синхронизации и обновите источник в приложении либо дождитесь фоновой проверки.

Приложение старается не ломать напоминания на кратковременно пустых или частично синхронизированных файлах и в таких случаях опирается на локальный кэш.

```powershell

```

## Ограничения текущей версии

- приложение работает только на Android
- для максимально точных напоминаний на новых версиях Android нужен доступ к exact alarms
- прямое открытие markdown-файла зависит от того, как источник был выбран через Android picker
- приложение не заменяет полноценный таск-менеджер и не синхронизирует данные само: оно работает поверх ваших markdown-файлов
