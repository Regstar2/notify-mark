# ObsidianNotification

Android-приложение для напоминаний поверх markdown-задач из Obsidian. Прототип v0.7.0 умеет выбрать одну заметку или папку с заметками через Storage Access Framework, отслеживать изменения, показывать статусы задач, синхронизировать alarm-ы, повторять уведомления по заданному режиму, восстанавливать напоминания из локального кэша и читать расширенный формат задач с `@due(...)`, тегами и приоритетами.

## Синтаксис

Активной считается строка markdown-задачи:

```markdown
- [ ] Купить лекарство @due(2026-04-20 19:00) @repeat(15m) @tag(health pharmacy) @priority(high)
- [ ] Позвонить врачу @due(2026-04-20)
- [ ] Проверить ответ @due(19:00) @repeatUntilDone(15m) #inbox
- [ ] Позвонить врачу @2026-04-20 14:30 every 15m
- [ ] Проверить Syncthing @20.04.2026 19:00 каждые 10м
- [ ] Быстрая задача @09:30 repeat 1h
- [ ] Пить воду @09:00 @repeat(2h)
- [ ] Проверить ответ @10:00 @repeatUntilDone(15m)
- [x] Выполненная задача не попадет в список
```

Поддерживается:

- `- [ ]`, `* [ ]` или `+ [ ]` для активных задач.
- Единый формат времени: `@due(2026-04-20 14:30)`, `@due(2026-04-20T14:30)`, `@due(20.04.2026 14:30)`, `@due(2026-04-20)` или `@due(14:30)`.
- Для задач только с датой используется время `09:00`.
- Legacy-время по-прежнему работает: `@2026-04-20 14:30`, `@2026-04-20T14:30`, `@20.04.2026 14:30`, `@2026-04-20` или `@14:30`.
- Простой повтор: `@repeat(15m)`, `every 15m`, `repeat 1h`, `каждые 10м`, `повтор 1ч`.
- Повтор до выполнения: `@repeatUntilDone(15m)`.
- Задача без `@repeat(...)` не повторяется.
- Теги: `@tag(health pharmacy)`, `@tag(health, pharmacy)` и обычные Obsidian-теги `#health`.
- Приоритет: `@priority(low)`, `@priority(medium)`, `@priority(high)`, `@priority(urgent)`, а также `p1`/`p2`/`p3`/`p4`.
- Ключевые слова `due`, `repeat`, `repeatUntilDone`, `tag` и `priority` можно изменить в настройках. Дефолтные ключи остаются совместимыми.
- Ошибки формата даты, времени, повтора и приоритета показываются в статусе приложения с файлом и номером строки.

## Поведение уведомлений v0.2.0

При чтении заметки приложение отменяет старые запланированные напоминания и планирует новые для активных задач с будущим временем. Для задачи с прошедшим временем и интервалом повтора приложение вычисляет ближайшее будущее срабатывание, но пока планирует только одно уведомление на задачу. Полный цикл повторов до отметки `- [x]` остается следующим этапом.

На Android 13+ приложение запрашивает разрешение `POST_NOTIFICATIONS`. Если разрешение не выдано, напоминания не планируются, а в интерфейсе показывается соответствующий статус.

## Поведение повторов v0.3.0

`@repeat(15m)` означает простой повтор каждые 15 минут. Уведомление после срабатывания само планирует следующее. Такой повтор останавливается при следующем чтении заметки, если задача уже не активна.

`@repeatUntilDone(15m)` означает повтор каждые 15 минут до выполнения. Перед каждым уведомлением приложение перечитывает выбранную заметку, ищет активную задачу с тем же ключом и не показывает уведомление, если задача уже отмечена как `- [x]` или удалена.

При ручном обновлении заметки приложение синхронизирует список alarm-ов: не создает дубликаты для той же задачи и не трогает уже запланированный будущий повтор, если задача не изменилась.

## v0.3.1

Если `@repeatUntilDone(...)` не может перечитать заметку в момент срабатывания alarm-а, уведомление теперь все равно показывается и планирует следующую проверку. Повтор останавливается только когда приложение смогло прочитать заметку и задача точно больше не активна.

## v0.3.2

Повторяющиеся уведомления теперь публикуются как новые уведомления на каждое срабатывание, а не как обновление уже висящего уведомления. Это нужно, чтобы Android снова проигрывал звук/вибрацию, даже если предыдущее уведомление пользователь не смахнул. Также добавлен новый канал `task_reminders_loud` с высокой важностью.

## v0.3.3

Повторы переведены на `AlarmManager.setAlarmClock(...)`, чтобы Android не откладывал минутные напоминания как обычные фоновые alarm-ы. Время в уведомлении теперь ставится по фактическому моменту показа, а не по исходному времени первого alarm-а. Добавлен новый канал `task_reminders_aggressive`.

## v0.3.4

Добавлено разрешение `SCHEDULE_EXACT_ALARM` и кнопка перехода в системную выдачу точных напоминаний. Если точные alarm-ы не разрешены, приложение больше не падает при планировании, а использует обычный alarm fallback и сообщает об этом в статусе.

Приложение проверяет выбранную заметку в фоне примерно раз в минуту и в открытом интерфейсе примерно раз в 15 секунд. При успешном чтении оно заново синхронизирует активные задачи с alarm-ами. При временной ошибке чтения существующие уведомления не отменяются.

## Статус v0.6.0

- [x] Сохранять локальный кэш задач

После каждого успешного чтения приложение сохраняет активные задачи в локальный кэш. Если источник временно недоступен или SAF первые несколько проверок возвращает пустой файл при уже известных задачах, текущие напоминания не сбрасываются: приложение восстанавливает alarm-ы из кэша и пишет причину в локальный журнал ошибок. Если источник стабильно остается пустым, это принимается как реальное удаление задач и уведомления отменяются. После `BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`, `TIMEZONE_CHANGED`, `TIME_SET` и `DATE_CHANGED` приложение заново синхронизирует заметку и перепланирует уведомления с учетом текущего времени и часового пояса.
