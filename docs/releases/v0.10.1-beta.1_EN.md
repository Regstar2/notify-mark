## About this release

- **Version:** `v0.10.1-beta.1`
- **Channel:** beta
- **Release-notes preparation date:** 2026-10-01
- **Previous public version:** none; this is the first public beta
- **Android:** 8.0+ (`minSdk 26`)
- **applicationId:** `com.regstar.obsidiannotification`

This release is intended for public beta testing of the primary flow: connect Markdown, see tasks, receive a local reminder, and write a task change back to Markdown.

> [!WARNING]
> This is a prerelease. It is not claimed to be stable and should not be the only copy of important notes. Back up working Markdown files or use versioned synchronization before connecting them.

## Highlights

- **Local Markdown reminders** — tasks remain in Markdown while Android reminders are scheduled on-device.
- **Multiple source types** — app-owned storage, individual files, and folders through SAF.
- **Partial Obsidian Tasks compatibility** — common emoji metadata is supported, but not the complete plugin grammar.
- **Signed release APK** — publishing is blocked when CI, security audit, signature verification, or checksum validation fails.
- **GitHub Issues feedback** — dedicated forms are prepared for bugs and feature requests.

## Changes

### Added

- task list and calendar views;
- local notifications with complete, snooze, skip, and open actions;
- recurrence, `@repeatUntilDone(...)`, grace period, snooze, groups, tags, and priorities;
- Quick Settings tiles;
- individual files and folders through SAF;
- partial Obsidian Tasks metadata support for `📅`, `⏰`, `🔁`, `✅`, `❌`, priority emoji, `🆔`, and `⛔`;
- automated signed APK build and SHA-256 checksum.

### Changed

- repeat metadata is displayed more compactly on task cards;
- long task titles are easier to edit and inspect;
- handling around tags, block ids, parse warnings, and partial Obsidian due/reminder authoring was tightened.

### Security

- the release workflow reruns project CI on the exact release source;
- the APK passes the security audit and `apksigner verify`;
- the release keystore is materialized only in the temporary directory of the self-hosted runner;
- the app does not request `INTERNET`.

## Installation and updating

### New installation

1. Open [GitHub Release v0.10.1-beta.1](../../releases/tag/v0.10.1-beta.1).
2. Download `NotifyMark-v0.10.1-beta.1.apk` and `NotifyMark-v0.10.1-beta.1.apk.sha256`.
3. Verify the APK SHA-256 against the checksum file.
4. Allow APK installation from the selected source if Android requests it.
5. Install the APK.
6. On first launch, allow notifications; for precise reminder times, allow exact alarms if Android exposes the corresponding special access.
7. For external notes, select a file or folder through SAF.

### Checksum verification

```powershell
$Expected = ((Get-Content ".\NotifyMark-v0.10.1-beta.1.apk.sha256" -Raw).Trim() -split "\s+")[0]
$Actual = (Get-FileHash ".\NotifyMark-v0.10.1-beta.1.apk" -Algorithm SHA256).Hash
$Actual.ToLowerInvariant() -eq $Expected.ToLowerInvariant()
```

The final SHA-256 is calculated from the APK built from the release tag, verified by the workflow, and published in both the GitHub Release body and the `.apk.sha256` asset. This pre-tag document intentionally does not copy a hash from an earlier build.

### Updating from dev/debug builds

No supported public upgrade path is claimed yet because this is the first public beta.

If an installed dev/debug build uses another signing key, Android may reject an in-place release APK install. Back up important app-owned Markdown and settings that cannot be restored before removing the old build.

### Permissions

- **SAF** — the user selects a specific file/folder; NotifyMark retains a persistable read/write grant for the external source.
- **Notifications** — required to show reminders on Android versions with runtime notification permission.
- **Exact alarms** — `SCHEDULE_EXACT_ALARM` is used for precise timing; Android may require separate special access.
- **Boot completed** — used to restore schedules after reboot.
- **Vibrate** — used for notification vibration.

### Rollback

A guaranteed rollback path between this beta and earlier development builds is not claimed. Uninstalling the app can remove app-owned data; external SAF files remain with their document provider, but access may need to be granted again after reinstall.

## Known issues

### Partial Obsidian Tasks support

- **Not supported:** fenced `tasks` query blocks, query language, group/sort/custom filters.
- **Recurrence:** only the documented subset is mapped; `every ... when done`, `every year`, and other unsupported forms are not silently converted into a native rule.
- **Dates:** natural-language dates are not supported.
- **Triggers:** `⏳` and `🛫` alone do not create an Android reminder.
- **Details:** [v0.10.0 compatibility notes](../versions/v0.10.0-obsidian-tasks-plugin-compatibility.md).

### Android and external sources

- reminder accuracy depends on exact-alarm access and Android/vendor background restrictions;
- SAF access depends on the document provider and may require selecting the source again;
- `applicationId` still contains the previous project name.
