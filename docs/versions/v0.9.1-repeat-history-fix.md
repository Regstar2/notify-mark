# NotifyMark v0.9.1 — Repeat History Fix

## Goal

Keep past repeat occurrences visible after the markdown head advances, without changing markdown as the source of truth for the current head.

## Fixed issue

Skipping or completing a repeating task moved `@due` forward, but the previous occurrence disappeared from the calendar (and bulk actions could bypass repeat-series handling). Local `OccurrenceHistoryStore` records were already written for single-task flows; the calendar only plotted parsed markdown tasks.

## Implementation notes

- Added `TaskVisibleOccurrence` and `TaskCalendarProjection.mergeTasksByDate` to combine markdown tasks with history rows, dedupe duplicate history lines, and skip history when it still duplicates the same series due as the current markdown head.
- `MainActivity` calendar (month, week, year summaries, day list) now consumes the merged map. Historical rows are read-only (no swipe actions); status meta uses existing short status strings.
- Tasks tab: filters **Skipped** and **Completed** also append matching rows from `OccurrenceHistoryStore` (repeat resolutions no longer on the markdown line), read-only with a short history hint.
- `NoteStore.markTasksDone` / `markTasksSkipped` iterate `markTaskDone` / `markTaskSkipped` so bulk selection uses `RepeatSeriesManager` for repeating tasks like the single-task and notification paths.
- `TaskGrouping` exposes `bucketForHistoryRecord` and `isPrivateHistoryRecord` so group filters apply to history snapshots consistently.
