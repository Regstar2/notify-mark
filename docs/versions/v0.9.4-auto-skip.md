# NotifyMark v0.9.4 — Auto-skip

## Goal

Optional global **auto-skip**: after the task is overdue for a configured extra delay (`due + grace + autoSkipAfter`), the app marks the task **skipped** using the same flows as manual skip (`NoteStore.markTaskSkipped` → repeat series / markdown / reminders).

## New behavior

- **Off by default.** Enable in **Settings → Уведомления**.
- **Delay:** any whole number of minutes from **1** to **one week** (same upper bound as overdue grace in `ActionPreferences`), stored in `AutoSkipPreferences`. Configure in **Settings → Уведомления → Действия из уведомления** or in the **task editor** (checkbox + minutes; no markdown token on the task line). See **Help** / `docs/markdown-format.md` for user-facing description.
- **When sync runs** (`NoteChangeMonitor.syncNow`, `MainActivity` render path, `ReliabilityReceiver`): due auto-skips are applied first, then reminders and auto-skip alarms are replanned.
- **Per-task alarms:** `AutoSkipScheduler` uses `AlarmManager` (`setAlarmClock` when exact alarms allowed, else `set`) with a dedicated request-code range; `AutoSkipReceiver` performs skip + `syncNow(forceReschedule)`.

## Settings

- Section **Уведомления**, block **Действия из уведомления**: checkbox **Включить автопропуск**, field **Задержка автопропуска, минут** (shown when enabled), and the shared **Сохранить** button (same as snooze / repeat-until-done / overdue grace). Task editor: same controls under **Основное**; delay persists on field blur and on **Save**; enabling/disabling persists immediately from the checkbox.
- Saving that form runs **Перепланировать** logic (`rescheduleAll` / `syncNow`).

## Auto-skip calculation

`autoSkipAt = reminderAt + task.getOverdueGracePeriod() (else ActionPreferences overdue grace) + AutoSkipPreferences delay`

Implemented in `AutoSkipCalculator`.

## One-shot task behavior

- `NoteStore.markTaskSkipped` → `@skipped` on line (existing path).
- Reminder cancelled when skip succeeds (`AutoSkipExecutor` mirrors notification skip).
- Completed / already skipped: executor no-ops (re-read task before skip).

## Repeating task behavior

- Same as manual skip: `advanceRepeatSeriesIfNeeded` with `OccurrenceStatus.SKIPPED` when `hasRepeatSchedule()` (v0.9.1 flow: history + markdown head advance).
- Auto-skip does **not** implement a parallel markdown editor.

## Interaction with grace

Uses **`ObsidianTask.getOverdueGracePeriod()`** (resolved explicit `@grace` / parser resolution). If null, uses **`ActionPreferences.getOverdueGraceMinutes`** as in `TaskStatus.forTask` list behavior.

## Interaction with snooze

**Variant A (documented):** auto-skip deadline is **not** postponed by snooze. Snooze only affects the next **notification** trigger from `ReminderScheduler`; overdue + grace + delay still determine auto-skip eligibility from **original** `reminderAt`.

## Interaction with repeat-until-done

Auto-skip ends the current occurrence (skip or repeat advance); nag alarms for that occurrence stop when reminders are rescheduled after sync.

## Reliability behavior

- `ReliabilityReceiver` already calls `syncNow` + `ensureScheduled` → due auto-skips and future auto-skip alarms are refreshed on boot, package replace, timezone, time set, date changed.
- If exact alarms are denied, auto-skip uses inexact `set`; missed fires are caught on next **sync** (≤ ~1 min from `NoteChangeMonitor` background alarm + foreground reads).

## Known limitations

- **Snooze:** does not shift auto-skip deadline (by design; see above).
- **Inexact alarms** if exact permission missing → wall-clock accuracy depends on OEM; **missed alarm** recovered on next **sync** / app open.
- **Collision risk:** auto-skip request codes are in a fixed numeric range; theoretical collision with another `PendingIntent` using the same request code is unlikely but not formally proven for all devices.
- **No on-device / Wear** verification in this implementation pass.
- **Repeating / SAF / history** flows rely on existing `NoteStore` / `RepeatSeriesManager` tests plus manual checks.
