# v0.10.1 — Long task title editor UI

## Long task titles

- **Editor field «Задача»** is multiline for display: at least **3 visible lines** (`128dp` minimum height) and up to **8 lines**, with vertical scroll inside the field, word wrap, and no horizontal scrolling in the title field. The shared input wrapper no longer clamps multiline title fields to the normal `44dp` height. Line breaks are blocked at input; any pasted CR/LF is collapsed to spaces when building the markdown line so a single logical task line is preserved.
- **Task list cards** keep a compact title (up to **3** lines on the main list, **2** on the calendar row and subtask rows), `ellipsize=end`, and improved line breaking on API 23+ (`breakStrategy` / no hyphenation) so long markdown, links, and tags wrap more predictably beside the status chip.
- **Markdown preview** in the editor is a monospace line in a **horizontal** `ScrollView` so a very long raw checkbox line can be inspected without clipping when the preview section is expanded.
- **Tags** in the editor «Дополнительно» field are initialised with **`#` prefixes** when hash-tag syntax is enabled in settings, matching markdown (`#home #work/project`), without changing stored tag values in the model.
- **Block id** (`^blockid-demo`) stays part of the parsed display/editable title and raw line so write-back cannot drop it; the parser test asserts it remains after cleanup.
- **Parse warnings in the editor** are filtered to the lines that belong to the current editor markdown block (parent + indented subtasks), so a warning tied to another line in a large file is not shown while editing an unrelated task block.
- **`ObsidianTasksLineAuthoring.tryAppendDueAndReminder`**: if time normalisation fails after a date was appended, the partial `📅 …` fragment is rolled back so the builder is not left in a half-written emoji state (avoids confusing the Obsidian date scanner).

## Known limitations

- Block id is still edited as plain suffix text in the title field (no separate control); removing it in the editor removes it from markdown unless recovered elsewhere.
- Title normalisation only collapses newlines to spaces; other exotic whitespace is unchanged.
