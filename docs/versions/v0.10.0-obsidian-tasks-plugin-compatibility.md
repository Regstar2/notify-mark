# NotifyMark v0.10.0 — Obsidian Tasks Plugin Compatibility

## Goal

Read Obsidian Tasks-style emoji metadata on markdown task lines without breaking NotifyMark native syntax, schedule a single Android reminder per task, preserve unknown fragments on write-back, and document limitations.

## Supported syntax

- Checkbox tasks: `- [ ]`, `* [ ]`, `+ [ ]`, `1. [ ]`, `[x]`/`[X]` done, `[-]` cancelled, custom single-character statuses preserved with a parse warning.
- Dates (ISO `YYYY-MM-DD`): `➕`, `🛫`, `⏳`, `📅`, `✅`, `❌`.
- Reminder: `⏰ YYYY-MM-DD HH:mm`, `⏰ YYYY-MM-DD` (uses default reminder time from format settings), `⏰ HH:mm` combined with `📅` on the same line.
- Recurrence `🔁` (subset mapped to `RepeatRule`): `every day`, `every week`, `every month`, `every N days`, `every N weeks`, `every weekday`, `every week on Monday`…`Sunday`.
- `every day when done` / `every week when done`: **not** mapped to interval repeat; raw text is kept, `OBSIDIAN_RECURRENCE_UNSUPPORTED` warning is emitted, scheduler does not treat them as due-date repeats. Cards show an explicit “not supported” line (see UI below).
- Priority emoji: `🔺`, `⏫`, `🔼`, `🔽`, `⏬` mapped onto existing `TaskPriority` values.
- `🆔` task id and `⛔` dependencies: preserved in metadata and in markdown on write-back; not used for scheduling.

## Unsupported syntax

- Obsidian `tasks` fenced query blocks, query language, group by, sort by, custom filters.
- Full natural-language recurrence from Obsidian Tasks beyond the listed `🔁` phrases (including many edge cases).
- Natural-language dates (only `YYYY-MM-DD` in v0.10.0).
- Using `⏳` / `🛫` alone as Android notification triggers (no extra setting added in this version).

## Task format setting

**Settings → Формат задач → Совместимость строк задач**

- **Только NotifyMark**: emoji metadata is not interpreted for reminders or repeats.
- **Obsidian Tasks**: emoji metadata is interpreted; completion/skip prefers emoji write-back when the line looks like an Obsidian Tasks line.
- **Авто / смешанный** (default): both native and emoji metadata are interpreted; explicit `@due(...)` wins over conflicting emoji reminder/due; conflicts emit a parse warning.

## Parser behavior

- `TaskParser` detects `TaskSyntaxStyle` (`NATIVE`, `OBSIDIAN_TASKS`, `MIXED`, `UNKNOWN`).
- Parsed emoji fields live in `TaskLineMetadata` attached to `ObsidianTask`.
- Invalid emoji date/time fragments add warnings and do not crash parsing.
- Fenced code blocks are still ignored for task detection.

## Reminder behavior

Effective reminder time (AUTO / OBSIDIAN modes), in order:

1. Native `@due(...)` when present and parsed.
2. Otherwise native legacy inline `@` date/time fragments already supported by NotifyMark.
3. Otherwise `⏰` with full date+time, then `⏰` date + default time, then `⏰` time + `📅` date, then `📅` date + default time.

If native explicit due and emoji fields disagree on the instant, native wins, `TaskLineMetadata.hasObsidianMetadataConflict()` is set, and a parse error entry is recorded.

## Repeat behavior

- Mapped `🔁` phrases become `RepeatRule` when safe; otherwise recurrence text is kept on the line, `TaskLineMetadata.isRecurrenceUnsupported()` is true, and a parse warning is emitted.
- `every year` is not mapped (no year unit in `RepeatRule`).
- `every day when done` / `every week when done` are **not** mapped to `RepeatRule` (no silent `1d` / `1w`); they remain raw with unsupported + warning.
- Recurring series advance still uses `RepeatSeriesManager` / `TaskMarkdownWriter`: when the line contains Obsidian due markers, `📅` is updated together with native `@due(...)` rewrite.

## UI (task cards)

- Repeat row copy was tightened in **[v0.10.1 — Repeat card display compacting](v0.10.1-repeat-card-display-compacting.md)**: short Russian summary without a second `🔁` in the text (the row icon carries repeat), single-line ellipsis, and fixed short phrases for unsupported / when-done recurrence on cards. Full warning + raw English remains available via `formatFullPrimaryRepeat` for diagnostics.
- When the smart/file grouping label matches the file name already shown on the card, the **duplicate “контекст / файл”** line is omitted to save vertical space.

## Write-back behavior

- Native tasks: unchanged path in `TaskMarkdownWriter` / `NoteStore`.
- Obsidian-shaped lines (AUTO/OBSIDIAN modes): completing sets `[x]` and upserts a single `✅ YYYY-MM-DD` for “today” in the local time zone; skips use `[-]` and `❌ YYYY-MM-DD`; metadata markers are not stripped by these operations.
- Unit tests cover `ObsidianTasksWriteBack.applyComplete` / `rewriteObsidianDueDate` preservation of `🔁`, `📅`, `🆔`, `⛔`; full editor rename/save flows should still be verified manually on device.

## Display title

- Service emoji spans (`📅`, `⏰`, `🔁`, priority, `🆔`, `⛔`, etc.) are stripped from the **display title** only; the raw markdown line is unchanged. Unknown emoji in the user title remain visible.
- Long titles in the **task editor** and card layout: see **[v0.10.1 — Long task title editor UI](v0.10.1-long-task-title-editor-ui.md)**.

## Known limitations

- `TaskCache` does not round-trip `TaskLineMetadata` (cached tasks use empty metadata until the next full parse from markdown).
- Task editor preview still primarily emits native `@due(...)` unless extended later; compatibility mode affects parsing and write-back from list/notification flows first.
- Strategy B (duplicate completed line + new active line) is not implemented; Strategy A (single head line) only.
